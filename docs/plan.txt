1. ARCHITECTURAL PRINCIPLES & GOVERNANCE RULES
================================================================================
Rule 1: ZERO HARDCODING
  - No college names, semester dates, grading formulas, or exam timetables are
    hardcoded into the application codebase.
  - The application provides the generic execution system; the user provides
    their institution's data.

Rule 2: LOCAL-FIRST RELIABILITY
  - 100% of read and write interactions must succeed without network connectivity.
  - Local SQLite is the single source of truth for the mobile client.
  - Network is only required for:
      (a) Document upload & Gemini multimodal processing
      (b) Supabase PostgreSQL bidirectional cloud backup
      (c) Google Calendar push sync

Rule 3: DUAL-TRACK PROGRESS SEPARATION
  - Task Progress (Automatic):
      Derived deterministically from binary or multi-state status transitions
      across assignments, lab observations, lab records, and action items.
  - Learning Progress (Manual):
      Controlled strictly by the student via sliders (0% to 100%) and confidence
      ratings (1 to 10) per unit/chapter. Task completion NEVER overrides
      understanding, and understanding NEVER fakes task completion.

Rule 4: GEMINI API ISOLATION & SECURITY
  - The Gemini API Key MUST NEVER be embedded in the mobile binary or exposed
    over client network requests.
  - The Gemini API is strictly invoked on the Python FastAPI backend via the
    official `google-genai` SDK using server-side environment variables.

          5. GRADED            ("Graded" - evaluated with marks recorded)

          When status advances to `GRADED`, trigger numeric modal prompt:
          "Enter your marks: Obtained [___] / Maximum [___]" (e.g. 8.5 / 10).

  [X] 3.4 Laboratory Dual-State Tracking System (TAD 7 / PRD 12):
      - Data Model: `id`, `subject_id`, `experiment_number`, `title`,
        `date_conducted`, `observation_status`, `record_status`, `marks`, `max_marks`.
      - Observation State Machine (tracked separately from record):
          * PENDING   ("Observation Pending")
          * COMPLETED ("Observation Done")
          * SIGNED    ("Observation Signed by Faculty")
      - Record State Machine:
          * PENDING   ("Record Pending")
          * WRITTEN   ("Record Written")
          * SUBMITTED ("Record Submitted to Lab Instructor")
          * APPROVED  ("Record Approved & Graded")
      - Lab Progress Banner:

  [X] 3.5 Automatic Progress Rollup Formula (TAD 8.1 / PRD 12 & 21.1):
      - Automatic deterministic rollup rules:
          * Theory Subject Task Progress %:
            (Count(Submitted Hand + Submitted Moodle + Graded) / Total Assignments) * 100
          * Laboratory Subject Task Progress %:
            ((Count(Signed Observations) + Count(Approved Records)) / (Total Experiments * 2)) * 100
          * Semester Task Execution %:
            (Total Completed Academic Work Items / Total Tracked Work Items) * 100
